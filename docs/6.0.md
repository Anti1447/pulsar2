## Ball-prediction obs

After the presence flags, `AdvancedObsPadded` appends the ball's predicted position and velocity every 0.25s out to
2s: 8 slices of 6 floats, in the same team frame and scale as the ball at the top of the obs (`POS_COEF`,
`VEL_COEF`). Every earlier offset is unchanged. This is the common format among the RLBot botpack's GigaLearn bots
(GalactusV2 samples 0.25 / 0.5 / 1 / 1.5 / 2s).

The prediction is the engine's own ball simulation: `BallPredictor` (`RLGymCPP/Gamestates/BallPredictor.h`) runs the
ball alone in a car-less arena, since v3 RocketSim has no `BallPredTracker`. Each builder (one per arena) updates
it once per tick. While the ball follows the last prediction, it only shifts it and simulates the new ticks at the
end; a touch, a reset or a state setter re-simulates all 240 ticks. The unit tests check the slices against an
independent prediction, the orange flip, and that six touch-free steps reuse the prediction and still match a fresh
one.

A state with no arena (the RLBot client) must pass the slices in with `SetExternalBallPred`. With neither, the
builder fails loudly; it never fills in zeros.

## GalactusV2 and ChronosV2

From the RLBot v5 botpack (https://github.com/RLBot/botpack). Both are GigaLearnCPP bots, so their
`SHARED_HEAD.lt` + `POLICY.lt` load into our own `Model` classes. `GGLBotOpponent` (`GigaLearnCPP/src/private/`)
ports each bot's obs builder and action mask from its repo's inference code, with their quirks, and plays
deterministically (argmax), as they do in RLBot. Details are in `GGLBotOpponent.h`.

| | GalactusV2 | ChronosV2 |
|---|---|---|
| Repo | SoldierDoge/GalactusV2 @ 217324c | KingJake3113/Chronos @ 4f8fdd2 |
| Weights | `rlbot-run/galactus_v2/` | `rlbot-run/chronos_v2/` |
| Obs | `GalactusOBS(3)`, 258, with 5 ball-prediction samples | its `AdvancedObsPadded(3)`, 225, x-mirrored |
| Net (shared / policy) | 1024x2 / 1024x4, LeakyReLU | 960x2 / 960-800-640-640, ReLU |

Each folder has a `SOURCE.txt` with the commit. Neither repo has a license file, so the weights stay out of git
(`*.lt` is ignored) and must not be redistributed.

`actionDelay` matches: both were trained with 7 and this run uses 7 (decided 2026-11-02; it also matches the live
RLBot client).

Metrics: `GalactusV2/Goals For`, `/Goals Against`, `/Serve Iters`, the same for `ChronosV2`. These are cumulative
and saved in `RUNNING_STATS.json`, like Nexto's. As a check, a random-weight 6.0 policy in a smoke run lost 574–4,531
to GalactusV2 and 627–7,333 to ChronosV2.

## Nets

The value path below the shared head is 4 layers: critic trunk 2, then each head's own 2 (critic, both V-dagger
twins, goal critic). The heads keep 2 private layers because the V-dagger twins need them to stay different
functions. With residuals on, the 2-layer shared head has no residual block, and the 4-layer policy is a stem,
one block and a plain last layer. The whole net goes from 25.9M to 25.2M parameters.

An activation isn't stored in a checkpoint, so these settings live only in ExampleMain and apply only to 6.0.
The GCO lineage keeps 5.3's nets. The gap sensor's own small net (`GapState` in `Learner.cpp`, measurement
only) is still LeakyReLU.
