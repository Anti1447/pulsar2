## Hypothesis
H-010's +28 Elo (coupled fork over its fresh4 control, ~3.6 SE, one seed) is a real effect of the aux loss and not seed noise.
## Design (2026-11-22, user-directed "second seed coupled fork")
The original fork point (fresh4 1,176,651,776) rotated out of every folder (checkpointsToKeep=8), so a same-start replicate is impossible. Instead BOTH arms fork from fresh4's 1,678,274,560 (copied into checkpoints_gco_fresh4c2 and checkpoints_gco_fresh4k2): fresh4c2 = heads coupled (GGL_HEADS_COUPLE=0.1), fresh4k2 = detached (coupling 0, exactly fresh4's behaviour); both seed 456, +500M each (to ~2.18B), run in sequence by chain_fresh4pair.sh. A different start point AND a different seed, with the control run inside the same replicate. Lesson: copy the fork-point checkpoint into a protected folder before it rotates.
## Pre-registered read
Replicated if fresh4c2 beats fresh4k2 head to head by more than +15 Elo (3x SE ~ 7.5 per 128-arena run, plus margin) in the same sign as H-010 (+28). Opposite sign or |gap| < +10 = H-010 was seed noise. In-run policy guards as H-010.
