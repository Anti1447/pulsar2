## What changes mechanically (read before interpreting)
- `Learn()` accumulates the gradient over all minibatches and takes ONE optimizer step per epoch. So the old setting was 2 steps per 400k rows (1 per 200k) and the new one is 1 step per 800k rows: **4x fewer nudges per row at the same learning rate.** If each step moves the weights about a fixed amount (Adam/Muon-style, not verified), progress per row falls by about that factor, whatever the gradient quality. Total optimizer steps in a 5B run: 6,250 (old: 25,000). This is the main risk, and is why the learning rate is the first thing to revisit if the wall takes much longer.
- Learn pass per iteration: 32 accumulated minibatches (about 5.0 s measured in the first iterations at 800k rows). The first iterations ran 37k steps/s overall (a fresh policy while the machine was also compiling and starting the chain); read the settled rate at the first health read.
- Memory: the 800k-row buffers use about 1 GB each; host memory 12 of 23 GB used at the start (14 at 1.6M). Watch `free -g`; an OOM crash loop is a stop condition.
- The trust-region clip and the pipelined one-update lag: with one step per iteration the lag is a single step.

## Pre-registered predictions (written before the run, against the previous ts2 run at the same game time)
1. **Throughput** above the previous 55-62k steps/s: expected 80-120k (learn pass about 5 s per 800k rows against collection about 8.5 s).
2. **Policy movement per iteration** (`Policy Update Magnitude`) about 0.18-0.36 per iteration if the one step is a full-size step (this is the direct check of the fixed-step-size assumption); KL per iteration of order 0.001 or less; clip fraction near 0.
3. **Wall break:** later in steps than the 15 Hz runs' 580-860M (fresh3-equivalent 2.3-3.4B ts2 steps) by the nudge ratio, so the break may not occur inside 5B steps. If the 4B kickoff-mix switch arrives with the wall unbroken, the whole comparison reads pre-wall on every arm.
4. **Per-step data-quality gain:** the advantage estimates from 800k rows are less noisy; I expect `GCO/Critic Explained Variance` higher than the old run's 0.47 at the same step.
Falsifiers: update magnitude below 0.1 per iteration (the nudge-size assumption is wrong in the other direction), steps/s below 55k (the buffer or memory is the bottleneck), the touch ratio falling for 500M steps.
